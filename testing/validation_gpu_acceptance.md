# GPU-приёмка

Статус на 2026-11-09: приёмка завершена на RunPod, RTX PRO 6000 Blackwell
Server Edition (96 ГБ): 22 запуска для 11 сценариев / 7 моделей.
Результаты и ограничения — в [итоговом отчёте](validation_gpu_report.md).

Основной `config/qwen_image_21_kibm.yaml` не изменяется. Подготовка отдельных
конфигов (без запуска обучения):

```bash
python testing/make_validation_gpu_configs.py --data-root /ai-toolkit/datasets/kib_medium --edit-sample-image /path/to/reference.png
```

Для сокращённой приёмки разрешён отдельный явно заданный каталог с небольшими
train/val-поднаборами без пересечения содержимого. Сам проход проверяет все
примеры этого набора, без пропусков. Конфиги выполняют 3 обновления, накопление
из 2 микробатчей, val с N1=8/N2=2, сохранение на шаге 2 и финальном 3.

Для Edit-2511 до запуска подготовить `controls/train` и `controls/val` внутри
`--data-root`, с соответствием целям по именам файлов. Вместо
`/path/to/reference.png` указать существующий путь на сервере к контрольному
изображению для генераций. Генератор только создаёт YAML и не проверяет
доступность серверных файлов.

Порядок моделей: Qwen-Image → 2512 → Edit-2511 → MOSS SFT → MOSS Base → 2.1 Turbo → 2.1.
Запускать по одной: `python run.py testing/.validation-gpu-configs/<имя>.yaml`.
Не запускать основной конфиг на 2500 шагов для проверки.

Автоматические проверки повторяемости и resume:

```bash
python testing/run_validation_gpu_acceptance.py <тестовый.yaml> --report <результат.json>
python testing/run_validation_gpu_acceptance.py <тестовый.yaml> --report <результат.json> --resume
```

Для каждой модели зафиксировать:

- Ревизии модели/энкодеров, реальные dtype, отсутствие квантизации весов,
  версии Python/PyTorch/diffusers/transformers, GPU и свободную память.
- Стартовый/периодический/финальный val на 0, 2, 3; повторный проход на тех же
  весах (сбросив только дедупликацию вызова) и все три TensorBoard-тега при
  `log_every=100`. Отдельно записать совпадение RNG/входов и численную погрешность.
- Структуру checkpoint, FP32 `model.safetensors`, тип оптимизатора в
  `optimizer.bin`, соответствие samples сохранённым весам.
- Resume из каталога шага 2 с целевым шагом 3: val на 2 перед новым обновлением,
  затем на 3. Сравнить следующий шаг с выполнением без val из того же состояния.
- Простые входы и маску для моделей без обязательного контроля; один/несколько
  контролей, альтернативы, автоматический depth и маску с контролями — для
  Qwen-2.1, Edit-2511 и MOSS edit. Для Edit-2511 отдельно проверить
  `match_target_res: false/true` и ожидаемый отказ при отсутствии контролей.
  Для Qwen-Image/2512 и MOSS без edit контрольные входы должны давать явную ошибку.
- Контролируемую ошибку последней проверки и изменение файла входа:
  ни один из трёх val-тегов не должен получить новую точку.

После приёмки удалить только созданные тестовые файлы и ненужные скачанные
модели, сохранив зависимости Qwen-Image-2.1. Затем проверить пути основного
YAML и подготовку CLI без полного обучения. Отчёт должен различать успешные
проверки, ожидаемые отказы и непроверенные сценарии.
