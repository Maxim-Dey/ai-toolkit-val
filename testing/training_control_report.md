# CPU-проверка остановки и разогрева LR

Дата: 2026-11-09. Дополнение к `deterministic-val-loss` после прежней GPU-приёмки.

## Изменения

- POSIX `run.py` запускает вычисление в отдельной группе процессов до импорта PyTorch. Родитель принимает Ctrl+C/SIGINT и SIGTERM, передаёт сигнал обучению; через 5 секунд без завершения использует SIGTERM, ещё через 5 секунд — SIGKILL. Повторный сигнал сокращает ожидание. Оставшиеся работники удаляются и при обычном завершении. TensorBoard и другие группы не затрагиваются.
- Ctrl+C завершает всю очередь, включая `--recover`, с кодом 130. Прерывание не создаёт аварийного чекпоинта; несохранённые обновления теряются.
- Основной `config/qwen_image_21_kibm.yaml`: штатный `constant_with_warmup`, `num_warmup_steps: 100`, прежний базовый `lr: 0.0001`. Новый scheduler не реализовывался, defaults остальных конфигов не менялись.

## Проверки

Все запуски выполнены с `CUDA_VISIBLE_DEVICES=-1` и `NO_ALBUMENTATIONS_UPDATE=1`.

| Среда | Результат |
| --- | --- |
| Windows, локальный проект | 57 обнаруженных тестов: 52 прошли, 5 POSIX-тестов ожидаемо пропущены |
| Linux, сервер, только CPU | Все 9 тестов `testing.test_training_warmup` и `testing.test_process_control` прошли |
| Linux, CLI | `python -u run.py --help` завершился с кодом 0 через новый родительский процесс |
| Спецификация и diff | `openspec validate deterministic-val-loss --strict` и `git diff --check` прошли |

Локальная регрессия включает прежние 48 тестов из `testing.test_validation_config`,
`test_validation_manifest`, `test_validation_inputs`, `test_validation_loss`,
`test_validation_lifecycle`, `test_validation_conditions`, `test_validation_distributed`,
`test_validation_isolation`, `test_validation_qwen_edit`, `test_validation_qwen21_loading`.

Новые проверки LR используют настоящий `SDTrainer.hook_train_loop` с маленькой CPU-моделью:
значения на каждом из первых 110 обновлений, обе формы накопления, пропущенное обновление,
инъекция OOM без обращения к GPU, сохранение на шаге 50 и 60 дальнейших обновлений
после восстановления. Веса и scheduler совпали с непрерывным запуском.

Проверки остановки используют реальные Linux-процессы и PTY с передачей байта Ctrl+C:
отзывчивый процесс, группа с игнорированием SIGINT/SIGTERM, повторный Ctrl+C,
прямой SIGTERM, обычное завершение, ошибка, очистка потомков и сохранность отдельного процесса.

Попытка запустить на сервере весь прежний набор с отключённой GPU остановилась при импорте
стороннего OmniGen2/Triton-модуля: он обращается к CUDA при импорте. Этот код не изменялся.
Поэтому полный набор проверен локально, а новые Linux-проверки — отдельно на CPU сервера.
GPU-тесты и обучение не запускались. Исторические GPU-отчёты и их хеши не переписывались.

Изменения синхронизированы с `/workspace/ai-toolkit`, хеши 11 файлов совпали.
Основной YAML остаётся тем же, за исключением трёх добавленных строк разогрева LR;
его SHA-256: `bdd2b299443513dc145585ba9f2169b582e2143bb10988df2bb49581e9e33c2c`.
Обучение остановлено, вычисляющих GPU-процессов нет, TensorBoard отвечает на порте 6006
и продолжает отслеживать весь `/workspace/ai-toolkit/output`.
Результаты и чекпоинты прежнего запуска не изменены.
