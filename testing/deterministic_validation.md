# Детерминированный val-loss: CLI

Новый интерфейс: `train_datasets` с `train_path`, отдельно `val_datasets` с
`val_path`. Старый `datasets/folder_path` остаётся доступным. Одновременно
задавать `datasets` и `train_datasets` нельзя. `val_datasets` конфликтует с
`train.validation_config`. Без `val_datasets` новая валидация выключена;
явный пустой список — ошибка.

```yaml
train_datasets:
  - train_path: /data/train
    resolution: [1024]
val_datasets:
  - val_path: /data/val
    resolution: [1024]
    val_every_n_steps: 10
    val_seed_noise: 42
    val_level_noise_n: 10
    val_seed_noise_n: 2
```

Параметры val — целые числа (bool не допускается). Интервал и число реализаций
не меньше 1; число уровней чётное, не меньше 2. Для нескольких наборов все
четыре параметра должны совпадать. Значения по умолчанию — соответственно
10, 42, 10, 2. Val не наследует dropout, пути и аугментации train.
`random_crop`, `random_scale`, flip, dropout, shuffle, случайные контроли и
аугментации запрещены; `num_repeats` равен 1.

Маска применяется к loss отдельно от контролей. Поддержка входов определяется
обёрткой модели, в том числе для локальных весов:

| arch | Маска | Контроли |
| --- | --- | --- |
| `qwen_image` (Qwen-Image и 2512) | да | нет |
| `qwen_image_edit_plus` (Qwen-Image-Edit-2511) | да | обязательно один или несколько |
| `qwen_image_2` (2.1 и Turbo) | да | один или несколько |
| `moss_image`, `model_kwargs.edit: false` | да | нет |
| `moss_image`, `model_kwargs.edit: true` | да | один или несколько |

Неподдерживаемые входы вызывают ошибку до обучения. Они не удаляются и не
подставляются из train. Поддержка новых адаптеров не добавляется.

Для Edit-2511 задайте `name_or_path: Qwen/Qwen-Image-Edit-2511` и
`arch: qwen_image_edit_plus`. Каждый train/val-набор должен иметь собственные
контроли: пути `control_path` / `control_path_1/2/3` или генерацию `controls`.
Маска loss сама по себе не заменяет обязательный контроль.
В `model.model_kwargs.match_target_res` сохраняется штатное управление
размером контрольных изображений. Их VAE latent и формы фиксируются на CPU,
текст кодируется с теми же изображениями в том же порядке; во время val
зашумляется только цель. Для генераций `sample.samples` также нужен `ctrl_img`
или соответствующие `ctrl_img_1/2/3`.

Совместные контроли задаются по порядку, например для Qwen-Image-2.1:

```yaml
val_datasets:
  - val_path: /data/val
    mask_path: /data/val_masks
    mask_min_value: 0.1
    control_path_1: /data/reference_a
    control_path_2: /data/reference_b
```

Для альтернативного набора той же цели добавьте отдельную запись
`val_datasets` с тем же `val_path` и другими контрольными путями.
Цели сопоставляются с масками и контролями по имени файла без расширения;
расширения ищутся в порядке `.jpg`, `.jpeg`, `.png`, `.webp`.
Отсутствующий обязательный вход и совпадение содержимого train/val — ошибки.

SHA-256 содержимого задаёт идентичность цели. Манифест учитывает описания,
маски, порядок контролей и подготовку. Перемещение корня и перестановка
обхода не меняют идентичность; точные дубликаты устраняются.
Среднее вычисляется по проверкам, затем альтернативам, затем уникальным
целям. Для A со средними 2 и 4 и B со средним 9 результат равен 6.

Контроли фиксируются вместе с текстом и VAE latent и не кодируются заново
на каждой проверке. Случайные последовательности Python, NumPy и PyTorch,
режимы модулей и параметры loss восстанавливаются при выходе из val.

Поддержаны MSE, MAE, pseudo-Huber, wavelet и band, модельный scale,
маска, `loss_multiplier`, source-target, t0/FFT и нормировочные опции общего
loss. Неизвестный loss отвергается. Отдельные teacher/stepped/guidance-проходы,
mean-flow, feature-extractor и адаптерные losses без пути чтения состояния
отвергаются preflight; обычный MSE вместо них не подставляется.
Табличные веса интерполируются по timestep. SNR допускается только при
наличии однозначной таблицы на всём диапазоне val; обычный flowmatch scheduler
такой SNR-таблицы не предоставляет. `timestep_type: shift` сам по себе не
включает взвешивание loss.

Каждый набор проверяется `N1 × N2` раз с батчем 1. При значениях 10 и 2 это
20 предсказаний на набор за проход. Стоимость увеличивается с количеством
альтернатив и разрешений; вес каждой уникальной цели остаётся одинаковым.

`train.steps` в новом режиме считает завершённые обновления оптимизатора.

Основной `config/qwen_image_21_kibm.yaml` использует штатный разогрев LR:

```yaml
train:
  lr: 0.0001
  lr_scheduler: constant_with_warmup
  lr_scheduler_params:
    num_warmup_steps: 100
```

LR начинается с нуля, после 50 завершённых обновлений равен `0.00005`,
после 100 — `0.0001` и дальше остаётся постоянным. Накопление градиентов,
val и пропущенные обновления не продвигают scheduler. Resume с теми же
параметрами продолжает сохранённое расписание, не начинает разогрев заново.

При `batch_size: 8`, `gradient_accumulation: 2` одно обновление использует
16 примеров на процесс; `val_every_n_steps: 10` означает 10 обновлений.
Пропуски и OOM не увеличивают шаг. Для 25 обновлений с интервалом 10 val
выполняется на 0, 10, 20, 25. Resume с 20 до 30 даёт новую оценку на 20 и 30.

TensorBoard создаётся автоматически: явный `log_dir` используется как каталог
запуска, иначе `<training_folder>/<name>/tensorboard/`. Общий журнал содержит
train `loss` и три тега: `val_loss_mean`, `val_loss_low_noise`,
`val_loss_high_noise`. Val записывается после полного успешного прохода с flush,
независимо от `log_every`. При resume события начиная с восстановленного шага
скрываются механизмом `purge_step`; более ранняя история сохраняется.

Для остановки CLI на Linux нажмите `Ctrl+C` в терминале запуска. Если
вычисление не отвечает, через 5 секунд ему передаётся SIGTERM, ещё через
5 секунд оставшиеся процессы завершаются принудительно. Повторный `Ctrl+C`
сокращает ожидание. Это действует и с `--recover`: очередь прекращается.
Дочерние процессы загрузки данных и компиляции также останавливаются;
TensorBoard продолжает работать. Несохранённые обновления теряются:
остановка не создаёт аварийный чекпоинт из потенциально неполного состояния.

Новый LoRA-чекпоинт: `<name>-stepNNNNNN/model.safetensors` (FP32) и
`optimizer.bin` (версионированное состояние оптимизатора, scheduler, RNG, EMA,
обучаемого SNR и манифест val). `complete.json` публикуется последним и
связывает файлы идентификатором состояния. Если используется EMA, модель и
samples получают EMA-веса, а состояние для продолжения сохраняет также
обучающие веса. Ротация удаляет завершённый каталог целиком.

Генерации лежат в `samples/` соответствующего шага. Каталог с одними samples,
включая шаг 0, не является чекпоинтом. Повторное финальное сохранение того же
шага не создаёт копий. Конфиг и TensorBoard остаются в корне запуска.

Автоматическое продолжение выбирает наибольший завершённый шаг. Для явного
выбора задайте `resume_from: /output/name/name-step000050` на уровне process.
Состояния разных шагов не смешиваются. Старую LoRA можно использовать через
`network.pretrained_lora_path` с новым именем запуска; старый `optimizer.pt`
не считается точным resume нового режима. Для отката используйте старый
конфиг `datasets` и прежние чекпоинты; автоматическая миграция не выполняется.
